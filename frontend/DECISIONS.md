# Part 1 — decisions where the spec was silent (one line each)

- Router: `react-router-dom` v6 (free, React 18 compatible); every route is a lazy chunk.
- Fonts: the spec's Google Fonts, self-hosted via Fontsource (same OFL files) so the PWA works offline and the browser makes no third-party requests; only the latin `wght` files plus the Devanagari/Telugu script files are declared (`src/styles/fonts.css`).
- Tailwind 3.4 (JS config) mapping colours to the CSS variables in `tokens.css` via `color-mix(... <alpha-value>)`, so opacity modifiers like `bg-conflict/15` work in both themes.
- Light theme verdict colours are darker variants (#c8382d, #a35f00, #17855a, #4d56c9) so text on them passes AA on the paper background; `--on-verdict` gives the text colour on solid badges.
- `@react-three/fiber` 8 (v9 requires React 19); `three` pinned to 0.170.x.
- `@react-three/drei` is not used: importing `RoundedBox` pulled ~50 kB gzip of drei into the hero chunk; three's own `RoundedBoxGeometry` does the same job. Re-add drei only if a later phase needs it.
- No Rollup `manualChunks`: it pulled React into the three chunk; natural splitting keeps three in `Hero3D` and lenis in `Landing`. `npm run check:chunks` verifies this by chunk content.
- i18n keys are flat and dotted (`keySeparator: false`) with `{name}` placeholders, so `shared/messages.en.json` keys and templates are copied verbatim.
- `categories.*` names are lower-case because they are interpolated mid-sentence ("this counts as peanut"); `basis.per_100g` = "100 g" because templates read "per {basis}".
- "or" joining uses `Intl.ListFormat(lang + "-IN", { type: "disjunction" })`; numbers use `Intl.NumberFormat(lang + "-IN")` (Indian digit grouping).
- `renderMessage` shows "—" for a missing param (never a raw `{placeholder}`) and falls back to English, then to the key.
- `Correction.field_path` format: dot keys + bracket indices, e.g. `ingredients[3].name`, `nutrition.rows[2].values[0].amount` (`src/lib/fieldPath.ts`).
- Mock `scan`/`recheck` return only the fixture reports whose `profile_id` was sent (no profiles → extraction only, matching the first-run rule); `?mockError=<CODE>` is read when the call starts.
- "Try the demo label" stores the fixture family as the scan's profiles without touching the user's saved profiles.
- Hero chips are positioned from the fixture's evidence boxes; the 3D camera is placed so the label face matches the DOM overlay rectangle exactly. Under 640 px the word chip morphs into its verdict tag in place (no room to stack).
- Scroll-linked values use function transforms (`useScrollRange`): Motion's accelerated scroll timelines did not clamp after the last keyframe, so chips faded back out.
- Lenis runs on the landing page only this phase (spec allows About too, but the phase rule keeps Lenis inside the landing chunk).
- Scan route is a photo-upload flow in Phase 1 so loading/error paths are exercisable; the live camera replaces it in Phase 2.
- Phase 2: `react-zoom-pan-pinch` pinned to 3.7 (v4 targets React 19 and warns about `ref` under React 18); same API except `onTransformed`.
- The zoomable content is exactly the viewer's size with the fitted photo centred inside it, so `focusTransform` (lib/boxMath.ts) is plain arithmetic; evidence outlines divide their stroke by the zoom because `non-scaling-stroke` ignores the parent's CSS scale.
- Mobile result layout keeps the photo viewer sticky under the header (collapsible), so tapping any chip shows the zoom without scrolling.
- No auto-capture (overrides spec §5.2): a photo is taken only when the user taps the shutter. Auto-capture fired as soon as camera permission was granted and photographed whatever was in front of the lens. The live checks still drive the hint and the shutter ring, which fills to show "ready".
- Live coaching reports motion as `quality.blurry` ("Hold steady") — the contract's `QualityIssue` has no motion value and the message fits.
- Evidence with a box but no text (an unreadable region) shows a "Hard-to-read area on the photo" chip, so every unknown flag can still be traced to the photo; unknown verdicts with a located region get a "Retake this area" button inline.
- Template summary (when `summary_lang ≠ lang`) = `{name} — {overall}. {first worst message}`, built only from fixed message keys.
- The `?debug=1` calibration overlay is developer-only and deliberately untranslated.
- Phone testing uses `vite preview` (production build) behind a cloudflared quick tunnel; `preview` shares the dev server's host/allowedHosts/proxy settings.
- Phase 4: the WebGL hero loads on the first interaction (pointer/touch/scroll/key), not on idle — probing WebGL at render cost ~400 ms of main thread on Lighthouse's mobile profile. Until then a raster WebP poster (rendered from the sample-label SVG by sharp at build time) is the LCP image.
- Hindi/Telugu dictionaries load on demand (a saved non-English language is loaded before first render); English stays in the entry chunk as the fallback.
- Motion uses `LazyMotion` + `m.*` with `domMax` in its own chunk (layout animations need it); entry chunk 150 → 102 kB gzip.
- Correction, explain, answer, profile-editor and parse-confirm sheets are `React.lazy` and mount on first open, then stay mounted so their close animation plays (`useLatch`).
- A `touch:` Tailwind variant (`@media (pointer: coarse)`) grows small controls to 44 px on phones only; on the narrowest phones (< 420 px) the header wordmark becomes screen-reader-only so the language switch fits at 44 px.
- Light-theme `--beam` (#07707e) and `--not-listed` (#11734d) were darkened to pass WCAG AA as text on the light surfaces.
- Install: Chrome/Edge use the captured `beforeinstallprompt`; iOS Safari gets a sheet with Share → Add to Home Screen steps; the button hides in standalone mode.
- About metrics: shown as accuracy only when `dataset_kind === "real"` and `real_packets > 0`; synthetic runs show "coming soon" plus a software-tests note. On phones the confusion-table column headers are icon-only badges (label kept for screen readers and as a tooltip); the row badges carry the full labels.
- `?mockScenario=unreadable` builds an unknown report for every profile sent (and applies to rechecks too), so families created in the app get cards in mock mode.
- In demo mode a failed `/api/recheck` (language switch, correction) falls back to the mock recheck, so the demo works with no backend.
- The service worker precaches the app shell only; `/api` is never cached or served from the navigation fallback. An offline banner says the demo still works and scanning needs a connection.
- A correction marks the corrected nutrient value or ingredient `readability: "clear"` (the user read it off the pack) so the engine uses it, and a renamed ingredient's `raw_text` follows its `name` so verdict messages quote the user's words; before, a typed-in value for a smudged row left the verdict at Can't determine.
- Result screen opens on the Nutrition tab, and the tabs read Nutrition · Ingredients · Verdicts · Couldn't read (team request); the family strip above the tabs still shows each person's overall verdict.
- Nutrition tab: "Calories per gram of protein" card (team request) from the engine's per-100 values. Team-supplied scale (kcal per g protein): ≤ 10 Excellent, ≤ 15 Very good (greens), ≤ 20 Good (yellow), ≤ 30 Moderate (orange), ≤ 50 Poor, > 50 Very poor (reds), 0 g protein = No protein (near-black, ratio undefined). The rating and interpretation are always written next to the colour. A missing or possibly misread calorie/protein value shows "can't work out" instead of a rating.
- Nutrition table: per-100 values the engine worked out (not printed in that column) carry a "Calculated" tag and an explanatory line; a row that can't be worked out says "Can't calculate", not "Can't read".
- The scan screen asks `/api/health` once and, when Gemini is down, says before the photo that scans use the slower on-device reader (Ollama up) or basic reading only (nothing up). No notice while waiting, when the AI reader is up, or when the backend can't be reached (the scan reports that itself). New hi/te strings `scan.reader.*` need native-speaker review.
- Contradictions panel ("These don't agree"): each disagreement shows both sides' words on the photo, who it affects and two actions, "Fix a misread" (correction sheet for that field) and "I checked the pack". The check is saved with the scan (`extraction.checked_contradictions`, kept in IndexedDB with the last scan) and every verdict is rechecked; it shows as checked at once. For a disputed number the button reads "The pack says {value}" and also records that value as a correction, so the number becomes usable. The summary strip above the tabs counts only unchecked disagreements.
- Confirmation prompt: a "Check this" or unknown result about an unclear ingredient asks "does {term} contain {category}?" and saves one correction per category (`ingredients[i].confirmations.<category>`), then rechecks. An unknown ingredient offers only "No": "Yes" needs a real ingredient name (through Fix), not a guess.
