# Part 2 decisions (where the spec was silent or had to bend)

- Python 3.12 venv at the repo root: `rapidocr-onnxruntime` 1.4.x (bundles its models, works offline) requires Python < 3.13.
- `opencv-python` instead of `opencv-python-headless`: rapidocr-onnxruntime depends on `opencv-python`; installing both clobbers the shared `cv2` module.
- OCR words come from RapidOCR per-character boxes (`return_word_box=True`); a gap > 0.45 x line height starts a new word, because the recogniser drops spaces between Latin words ("EdibleVegetable"). The spec's proportional split is the fallback when a line has no character boxes. Fixture-label recall went from 80 % to 96 %.
- `glare_ratio` follows the contract (fraction of pixels with every channel >= 250). A digital pure-white page scores very high; real photos rarely clip paper. Blur (100) and glare (3 %) thresholds are provisional until calibrated on real packet photos.
- `cropped_edge`: at least 3 tokens and at least 10 % of an image's tokens within 1 % of a border.
- Error codes: no images -> 400 `VALIDATION`; > MAX_IMAGES -> 400 `TOO_MANY_IMAGES`; file > MAX_IMAGE_MB or body > MAX_IMAGES x MAX_IMAGE_MB + 1 MB -> 413 `BAD_IMAGE`; undecodable/unsupported file -> 422 `BAD_IMAGE`; unknown route -> 404 `NOT_FOUND`; anything unexpected -> 500 `INTERNAL` without details.
- Accepted image formats: JPEG (incl. MPO), PNG, WebP; HEIF only if the installed Pillow can open it (no extra plugin).
- Phase 1 `/api/scan` validates the form, decodes every image, then returns `shared/fixtures/scan_result.json` with the requested `lang`.
- `/api/health`: Gemini is "up" when a key is set and `GET v1beta/models` returns 200 (no generation quota used); Ollama when `GET /api/tags` returns 200. 3 s timeout each, cached 60 s.
- Extra modules beyond the spec tree: `errors.py` (ApiError), `fixtures.py` (validated fixture loading), `provider_probe.py` (health checks), `pipeline/assemble.py` (EngineOutput -> ScanResult, shared by scan and recheck), `scripts/ocr_probe.py` (time OCR on one photo).
- `backend/pytest.ini` holds pytest config (root config files belong to `main`).

## Phase 2
- One structuring call per scan covers all panels: the LLM schema has a `panels[]` list (one level, no recursion); alignment and merge then run per panel.
- LLM-facing JSON schema: `$ref`s inlined and **every property required** (null / [] allowed). With optional fields, constrained decoding let gemma3 skip `ingredients` entirely.
- Window search (alignment step 2) only accepts windows between 0.8x and 1.5x(+4) of the item's length, so "Sugar" cannot verify "Invert Sugar Syrup", and over-wide citations get narrowed. Ties go to the window nearest the cited tokens.
- Nutrient numbers: verified -> parsed from OCR text (OCR wins, `llm_ocr_number_mismatch:<key>`); located only by the model's box -> kept but `partial`; not found on the photo at all -> amount None, `unreadable`, issue `value_not_on_photo:<key>` (gemma3 invented "175 mg" for a smudged sodium value).
- Sub-ingredient `parent_index` is accepted only if the child's text appears inside the parent's printed text (gemma3 set parent 0 on every item).
- Statement ids `alg_N`, claim ids `clm_N` (same as the fixture).
- Cache key = image bytes + order + panel hints + PROMPT_VERSION + GEMINI_MODEL; language is not part of it (extraction does not depend on it). `ocr_only` results are never cached.
- OCR-only: a token ending in `)`/`),`/`).` resets bracket depth (OCR garbles brackets); nutrition rows are read only below a "Nutrition" heading; veg mark is always `unclear`.
- Scan budget 45 s: the LLM call gets what is left minus 5 s; on timeout or all-providers-failed the scan degrades to OCR-only instead of failing. A route-level 45 s guard returns 503 `LLM_UNAVAILABLE`.
- Router: a provider that times out is skipped for 300 s (like a 429 cooldown). On this M2 Mac, gemma3:4b needs ~120 s for a full extraction (30 tok/s output), so without Gemini the first scan waits 30 s and later scans go OCR-only in ~1 s.
- Ollama `num_ctx` = 8192: the default context truncates the prompt, and the OCR list comes last.
- Gemini: SDK retries disabled (`HttpRetryOptions(attempts=1)`), timeout in ms from `LLM_TIMEOUT_S`; the router owns fallback.
- The FakeLLM fixture `tests/data/ollama_test_label.json` is a real gemma3:4b recording (it includes realistic mistakes). The Gemini recording (`scripts/record_fake_llm.py gemini`) is added once a key is in `.env`.

## Phase 3
- Self-verification: each trigger reason is tried once; at most 2 LLM re-reads per scan within 25 s; further triggers are recorded as `skipped_budget`. Ingredient re-reads crop the whole ingredients block (not just the unreadable spot) so an accepted re-read is a complete list. Crop tokens get ids `img_N:r{round}t{K}`.
- "Couldn't read" items are derived, not stored: every verify trigger that still applies after verification becomes an `UnknownItem` with the region (`unknown.retake_region`, or `unknown.ingredients_truncated`). The same function serves scans, cache hits and `/api/recheck`, and follows profile changes (threshold triggers depend on profiles). Pipeline items replace engine items of the same (section, message_key).
- One 45 s deadline per scan; each LLM stage gets its cap minus a reserve for the stages after it, and is skipped below 3 s.
- User-facing prose (summaries, LLM explanations of unknown terms, hi/te translations of KB text) is taken from Gemini only. In a live test gemma3:4b wrote Telugu summaries with wrong ingredients and wrong state words. Without Gemini: no summaries (the frontend shows its reviewed templates), explain returns the English KB text, and unknown terms return 503 `LLM_UNAVAILABLE`.
- Ollama is still used where output is checked afterwards: region re-reads (aligned to the photo), profile parsing (catalog-validated, user confirms) and term interpretation (engine caps it at "possible").
- A summary must contain the exact state word for that profile's overall verdict (in the scan language), be ≤ 25 words and contain no banned word (en/hi/te), else it is dropped.
- A provider that times out on an image call is skipped for image calls for 300 s, but keeps serving short text tasks. Rate limits still cool a client down for everything.
- `/api/recheck` summaries: regenerated (8 s) only when the language changed; otherwise a stored summary is reused only for profiles whose (restriction, state, reason) results are unchanged. Unknown scan_id (restart) -> no summaries. Interpretations are reused per scan_id from an in-memory LRU (256 scans).
- Agent: Gemini function calling only (gemma3 has no tool support). The model's final turn is JSON; Gemini's own reply turns are sent back unchanged (thought signatures). Questions about "me"/"us" with no name answer for every profile, because AskRequest does not say who is asking.
- Keyword fallback maps hi/te/en ingredient words to KB categories through `engine.explain_term` ("दूध" -> milk), and quotes "may contain"/facility statements instead of answering "yes".
- Profile parsing: severity comes from wording first (allergic -> strict; avoid / trying to cut -> preference), then the model, then the catalog default. Needs the keyword matcher sees but the model dropped are returned as warnings for the confirmation screen.
- Shared fixed wording (state words, banned words, AI note) lives in `app/wording.py`; hi/te strings are marked for native-speaker review.
- `backend/app/fixtures.py` removed: every endpoint now does real work; tests load fixtures from `backend/tests/fixture_data.py`.

## Phase 4
- Gemini: one SDK client per key for the process lifetime; per-request timeout via `GenerateContentConfig.http_options`. A throw-away client per call was garbage-collected mid-request ("client has been closed"). Any SDK exception maps to `ProviderUnavailableError`, so it falls back instead of returning 500.
- Body size: a streaming ASGI limiter (also catches chunked uploads with no Content-Length). Scan: MAX_IMAGES x MAX_IMAGE_MB + 1 MB -> 413 `BAD_IMAGE`; JSON routes: 4 MB -> 413 `VALIDATION`. It sits inside the request-id/CORS middleware so the 413 is logged and readable by the browser.
- Images: HEIC/HEIF via `pillow-heif` (BSD-3). Over 50 MP is rejected before decoding. Big JPEGs are decoded with `draft()` at the smallest scale whose long side is still >= 2000 px; the original oriented size is kept for the low-resolution check.
- OCR: 3 worker threads (one per panel) and a 20 s timeout per image (no tokens on timeout); the self-check's crop OCR runs in the same pool instead of on the event loop.
- Cache hits need no LLM call: interpretations (with the list of terms already asked) and summaries (keyed by language + profile + verdict fingerprint) are stored next to the cached extraction (`<key>.extras.json`).
- `httpx`/`google_genai` loggers are set to WARNING (they log request URLs). A test runs scan/ask/explain/health with a fake key and checks logs for the key, prompt text, image bytes and line length.
- Docker: `python:3.12-slim` + `libgl1 libglib2.0-0` (rapidocr pulls `opencv-python`), runs as uid 1000 (Hugging Face requirement), copies `engine/*.py` + `engine/kb` + `shared/` + `backend/app`; image ~1.1 GB. Root `.dockerignore` is main-only, so `backend/Dockerfile.dockerignore` (BuildKit) limits the context.
- Hosting: Hugging Face refused to create the Docker Space (402: Docker Spaces on free CPU now need PRO), which breaks the free-only rule. The public backend goes to Render's free web service (spec's backup host) with `OCR_WORKERS=1` to stay inside 512 MB. The HF publisher script was removed.
- Gemini fallback model per key (`GEMINI_FALLBACK_MODEL`, default `gemini-flash-lite-latest`): Google's 503 overload and free-tier 429 quota are per model; on this key `gemini-flash-latest` returned 503 for hours while the lite model answered. Order: primary key x (main, fallback model), backup key x (main, fallback), Ollama. The agent tries each usable Gemini client in that order.
- Gemini request deadline is never below 15 s (Google returns 400 "Minimum allowed deadline is 10s" and expires 10 s deadlines); stage budgets are enforced client-side by the router's `wait_for`. Short-budget calls (summaries, re-reads) had been failing with 400 for this reason.
- LLM citations are word numbers per photo (`token_ids: [12, 13]`, mapped back through `structure.Citations`) instead of `"img_0:t12"` strings, and Gemini's schema leaves optional fields optional (Ollama still gets all-required). Output for the test label went from 3,804 to ~3,000 tokens. PROMPT_VERSION structure-v3.
- Cache hits never call an LLM: they use cached interpretations/summaries and leave missing summaries to the frontend templates (a hit had taken 18.6 s retrying summaries; now 0.02-0.06 s).
- Measured on the free tier on 2026-10-16: even "Say OK" took ~9 s on gemini-flash-lite-latest (queueing), structuring the test label 13-27 s, so fresh-scan p50 was ~40 s; the p50 <= 8 s target could not be met or fairly measured that day.
- Gemini 503 (model overloaded) cools that model down for 60 s like a 429, but is not reported as rate limiting; `GEMINI_FALLBACK_MODEL` takes a comma-separated chain. On 2026-10-16 every full Flash model (flash-latest, 3.5-3.8) returned 503 for minutes while the lite models answered, and gemma3:4b on a MacBook Air needed > 90 s per label, so scans fell to OCR-only.
- Focus before reading (`pipeline/focus.py`): RapidOCR's detector runs on a 2000 px copy, the text block with the most lines (+ blocks with >= 20 % of its lines, + lone long thin lines at its print size) is cropped with a 3 % margin from a <= 4000 px source, turned upright when most lines are vertical (90 vs 270 and 0 vs 180 chosen by OCR confidence) and enlarged to 2000 px (max 4x). OCR, Gemini and verification read that view; every Evidence/OcrToken box is mapped back to the full photo before caching. Gemini read 0 ingredients from a sideways ice-cream-cone photo and all of them from its focused view. Crops only when the text covers < 60 % of the photo; cache key carries FOCUS_VERSION.
- A caller's `timeout_s` to `LLMRouter.generate` is now the budget for the whole fallback chain (each attempt gets what is left, none under 2 s); before, every model in the chain got the full budget, so interpretation could take 16 s on a 10 s budget and push a scan past 45 s.
